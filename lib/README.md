# FIDO BLE HID Library Tests

This directory contains the implementation and tests for the FIDO BLE HID library.

## Test Structure

The tests are organized into several main categories:

1. **FIDO2 Authenticator Tests**:
   - **Fido2AuthenticatorTest.java**: Basic unit tests for individual methods
   - **Fido2AuthenticatorIntegrationTest.java**: Integration tests for end-to-end functionality
   - **Fido2AuthenticatorMockTest.java**: Mock-based tests that isolate the class from its dependencies

2. **CTAP Protocol Tests**:
   - **Ctap2HidRequestTest.java**: Tests that emulate CTAP2HID requests to verify protocol handling

3. **Data Layer Tests**:
   - **FernetKeyTest.java**: Tests for the `FernetKey` class, which implements the [Fernet specification](https://github.com/fernet/spec/blob/master/Spec.md) for symmetric encryption
   - **SymmetricKeyTest.java**: Tests for symmetric key operations

## Running the Tests

### Using Gradle

To run all tests:

```bash
./gradlew :lib:test
```

To run a specific test class:

```bash
./gradlew :lib:test --tests "com.isfs.blekey.authenticator.Fido2AuthenticatorTest"
```

### Using the Test Script

Alternatively, you can use the provided run_tests.sh script:

```bash
./lib/test/run_tests.sh all      # Run all tests
./lib/test/run_tests.sh unit     # Run only unit tests
./lib/test/run_tests.sh integration # Run only integration tests
./lib/test/run_tests.sh mock     # Run only mock tests
./lib/test/run_tests.sh ctap     # Run only CTAP2 HID request tests
./lib/test/run_tests.sh coverage # Run tests with JaCoCo code coverage
```

To run a specific test class:

```bash
./lib/test/run_tests.sh com.isfs.blekey.data.FernetKeyTest
```

## FernetKey Interoperability Tests

The FernetKey tests verify that the Java implementation of Fernet is compatible with the Python `cryptography.fernet` package. This ensures that tokens generated by one implementation can be decrypted by the other, providing interoperability between Java and Python systems.

### Prerequisites for FernetKey Tests

To run the FernetKey tests, you need:

1. Java JDK 17 or higher
2. Python 3.6 or higher
3. Python `cryptography` package

#### Installing the Python cryptography package

```bash
pip install cryptography
```

### What the FernetKey Tests Verify

The FernetKey test suite verifies the following:

1. **Key Generation Compatibility**: Keys generated by the Java `FernetKey` class can be used by Python's `cryptography.fernet` module.
2. **Java to Python Interoperability**: Tokens encrypted by the Java implementation can be successfully decrypted by the Python implementation.
3. **Python to Java Interoperability**: Tokens encrypted by the Python implementation can be successfully decrypted by the Java implementation.
4. **Error Handling**: The Java implementation correctly handles invalid tokens and expired tokens.

### How FernetKey Tests Work

The tests use an embedded Python script that is executed directly from the Java test class. This script provides the Python side of the verification process.

The test flow is as follows:

1. Generate a Fernet key using the Java implementation
2. Use the key to encrypt/decrypt data in both Java and Python
3. Verify that the results match the expected output

JaCoCo code coverage reports can be generated by running:

```bash

This will execute all tests and generate detailed coverage reports showing which lines of code were executed during the tests. The HTML coverage report will be available at:

```

The report includes:
- Overall project coverage metrics
- Package-level coverage statistics
- Class and method-level coverage details
- Line-by-line coverage visualization

XML reports are also generated for integration with CI tools at:

## Adding New Tests

When adding new tests:

1. Place them in the appropriate package under `lib/test/`
2. Follow the naming convention `*Test.java` for test classes
3. Use JUnit 5 annotations and assertions
4. Use Mockito for mocking dependencies when appropriate

## Test Dependencies

The tests use the following dependencies:

- JUnit 5 for test framework
- Mockito for mocking
- Mockito Inline for mocking static methods

These dependencies are configured in the `lib/build.gradle` file.

## Directory Structure

The test directory structure follows the same package structure as the main code:

```
lib/test/com/isfs/blekey/authenticator/
lib/test/com/isfs/blekey/ctap/
lib/test/com/isfs/blekey/data/
lib/test/com/isfs/blekey/util/
```

This keeps the tests separate from the main code while maintaining the same package structure.

## Troubleshooting

If you encounter issues with the FernetKey tests:

1. Ensure Python is in your PATH
2. Verify that the `cryptography` package is installed
3. Check the error output from the Python script execution

## Notes

- The `FernetKey` implementation uses a 30-day TTL for tokens by default.
- The test class passes data directly to the Python script via command-line arguments, eliminating the need for temporary files.
